AgentFocus Source

When a coding agent needs you, the click opens that tab.

You leave a few agents running in terminal tabs. One finishes, or it asks a question. A banner shows up. You click it, and the wrong window comes forward, or nothing does. Then you hunt for the tab that was asking.

AgentFocus is a menu-bar app for that, on macOS 13 or newer. A hook writes one small file on your Mac when the agent is waiting. The app posts the banner. You click it, and you land on the session that asked.

What a click does

  • Terminal.app: the exact tab, matched by tty.
  • VS Code, Cursor, Windsurf, and VSCodium: the window for that project folder.
  • Ghostty, kitty, and WezTerm: those apps notify on their own. AgentFocus stays quiet so you do not get two banners.
  • Option-Command-A focuses the next waiting session from anywhere.

It stays on the machine. No account, no network, no telemetry. It does not ask for Accessibility, Screen Recording, or Input Monitoring.

Who it is for

People who run coding agents in a terminal on a Mac. Claude Code is wired in today. Codex CLI, Copilot CLI, Goose, and OpenCode have shims. Agents that live only inside an editor chat panel are out of scope, because there is no shell hook and no tab to open.

Install

The npm package is not published yet. Clone the repo and run the installer. You need Node 18 or newer.

git clone https://github.com/no-hup/agentfocus cd agentfocus ./install.sh

./install.sh runs agentfocus init. That copies the CLI and hooks into your home folder, merges the Claude Code hooks into ~/.claude/settings.json without removing your other hooks, and launches the menu-bar app. Homebrew is written but not a live tap yet.

Limits, stated as they are

  • iTerm2 exact-session focus is implemented and not yet verified on a machine that has iTerm2.
  • tmux, SSH remotes, and devcontainers are not bridged.
  • The helper is ad-hoc signed. Upgrading to a new version asks for the Automation permission once more.
